Battleground Telemetry

Real-time analytics for a synthetic battle-royale game. Four independent event sources stream through Kafka and Flink into PostgreSQL, and live Apache Superset dashboards show the results. The pipeline stays correct when events arrive late, out of order or duplicated.

How it works

Simulator

Python. Match, gameplay, session and server sources on independent schedules.
→

Kafka

KRaft broker with versioned JSON contracts per topic.
→

Flink

Validation, 24-hour dedupe, watermarks, windows and checkpoints.
→

PostgreSQL

Canonical facts, manifest reconciliation and live views.
→

Superset

Four dashboards that refresh every 15 seconds.

Alongside the stream: rejected and late events go to dead-letter topics, dbt builds historical marts with tests, Airflow runs archive/reconcile/dbt/export batches, a Parquet archive supports replay, and Prometheus feeds real pipeline metrics into the reliability dashboard.

Engineering highlights

Correct under messy delivery

Duplicates leave results unchanged. Kill and placement counts come from immutable facts, not retried increments. Results stay provisional until they match the source manifest.

Late and bad data handled

Bounded lateness is accepted. Very late events are retained and corrected after reconciliation. Malformed input goes to a dead-letter topic while valid input keeps flowing.

Fault recovery tested

A checkpoint was taken, then the Flink TaskManager was stopped. Lag grew while it was down, and processing resumed from a newer checkpoint with identical outcomes.

Archive and replay

Runs are archived to Parquet with checksums and replayed into an isolated namespace. Replayed outcomes are compared against the originals.

Run it yourself

Needs Docker Compose, Python 3 and about 12 GB of RAM for Docker.

git clone https://github.com/gv1shnu/pubg.git && cd pubg
make bootstrap   # build, migrate, create topics, submit the Flink job
make demo        # 100-player match, about four minutes
make bi-up       # create the four Superset dashboards
# open http://localhost:8088

Single-broker portfolio deployment, not a production or high-availability service. All game and server data is synthetic, with no official PUBG affiliation. See guarantees and limits.
